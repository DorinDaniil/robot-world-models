# Архитектура системы обучения робота

Документ описывает, из каких компонентов состоит система «робот обучается задаче», как они
связаны и какие проектные решения принимаются на каждом уровне. Теория каждого компонента —
в лекциях (`docs/lectures/`), реализация — в `src/rwm/`.

## 1. Три класса методов

Агент взаимодействует со средой: получает наблюдение $o_t$, выдаёт действие $a_t$, получает
награду $r_t$. Методы различаются тем, что оценивается по данным.

| Класс | Что обучается | Источник данных | Типичная область применения |
|---|---|---|---|
| Model-free RL (SAC, PPO, TD3) | $\pi(a \mid o)$, $Q(o, a)$ | взаимодействие | симуляция с массовым параллелизмом; локомоция |
| Model-based RL / модели мира (Dreamer, TD-MPC) | $\hat p(z' \mid z, a)$, $\hat r$, затем $\pi$ или план | взаимодействие, на 1–2 порядка меньше шагов | симуляция с ограниченным бюджетом; обучение на устройстве |
| Обучение по демонстрациям (BC, ACT, Diffusion Policy, VLA) | $\pi(a_{t:t+k} \mid o)$ | телеоперация | физические манипуляторы |

На физических манипуляторах в настоящее время преобладает третий класс: сбор 50–200
демонстраций дешевле и безопаснее, чем исследование методом проб. Модели мира дают наилучшую
эффективность по данным в симуляции и исследуются как средство дообучения политик на реальных
записях. Курс следует порядку: симуляция → модели мира в симуляции → демонстрации на
устройстве → их сочетание.

## 2. Уровни системы

```
6. Устройство: цикл управления в реальном времени, перенос, безопасность
5. Инфраструктура эксперимента: конфиги, сиды, логи, чекпоинты, протокол оценки
4. Обучение: модель мира, актёр/критик, планировщик или политика по демонстрациям
3. Данные: буфер последовательностей / датасет демонстраций
2. Среда (Gymnasium): reset/step, пространства, награда, семплирование задачи
1. Модель робота и физика: MJCF, MuJoCo, актуаторы
```

### 2.1. Модель робота и физика

Робот задаётся деревом тел (MJCF), шарнирами, геометриями и актуаторами (лекция 2, §2.7).
Ключевые решения: тип актуатора (в курсе — позиционный ПД, соответствующий сервоприводам),
шаг физики $\Delta t$ и число шагов на одно действие агента. Модели реальных рук берутся из
`mujoco_menagerie`; учебная рука `assets/arm3.xml` имеет 3 степени свободы и служит для
того, чтобы все вычисления были обозримы.

### 2.2. Среда

Интерфейс Gymnasium: `reset(seed) → (obs, info)`, `step(a) → (obs, r, terminated, truncated,
info)`. Проектируются:

- пространство наблюдений (`state` для отладки, `pixels` для постановки, близкой к устройству);
- пространство действий, нормированное в $[-1, 1]^m$; семантика — приращение целевых углов
  (локальное действие) либо приращение положения конца с обратной кинематикой;
- награда (плотная на этапе отладки, разреженная — как целевая постановка) и независимая
  от награды метрика успеха;
- раздельные флаги завершения и усечения (лекция 1, §1.4);
- семплирование задачи в `reset` с гарантией достижимости (через прямую кинематику).

Реализация: `src/rwm/envs/base.py` (физика, рендер), `src/rwm/envs/reach.py` (задача).

### 2.3. Данные

Модели мира обучаются на подпоследовательностях длины $T$ (от 3 у TD-MPC2 до 64 у Dreamer),
поэтому буфер хранит эпизоды целиком и семплирует окна, не пересекающие границ эпизодов.
Изображения хранятся в `uint8`. Для демонстраций используется датасет фиксированного
формата с синхронизированными потоками камер и энкодеров.

### 2.4. Обучение

Общие компоненты модели мира: энкодер $o \to z$, латентная динамика $(z, a) \to z'$, головы
награды и продолжения, опционально декодер; затем либо актёр-критик в воображении (Dreamer,
лекция 3), либо планировщик с терминальной ценностью (TD-MPC2, лекция 4). Цикл обучения
един: предзаполнение буфера → (действие, запись, обновление, оценка, логирование).

### 2.5. Инфраструктура эксперимента

- Конфигурация в YAML; один файл — один эксперимент; в коде нет констант, влияющих на
  результат.
- Сиды для среды, NumPy и PyTorch; результат — среднее по $\ge 3$ сидам со стандартной ошибкой.
- Логи: доходность, доля успехов, длина эпизода, компоненты лосса, нормы градиентов,
  скорость (шагов среды/с); для моделей мира — ошибка открытого цикла по горизонту.
- Оценка: отдельная среда, детерминированная политика, фиксированные сиды, $\ge 10$ эпизодов.
- Параллельные среды: `gymnasium.vector` (процессы) для MuJoCo на CPU; MJX/Isaac Lab для
  тысяч сред на GPU.
- Чекпоинты модели и оптимизатора; буфер — опционально.

### 2.6. Устройство

Цикл управления с измеренной задержкой, рандомизация домена при обучении, идентификация
параметров сервоприводов, ограничения безопасности на уровне контроллера (лекция 5).
Телеоперация и датасеты — через LeRobot; рука SO-101 имеет MJCF-модель, что позволяет
использовать одну постановку задачи в симуляции и на устройстве.

## 3. Типичные ошибки проектирования

1. Начинать с пиксельных наблюдений до того, как алгоритм отлажен на векторе состояния.
2. Начинать с полной модели промышленного манипулятора до того, как понятна учебная.
3. Сравнивать методы по доходности, а не по доле успехов (доходность зависит от формы награды).
4. Делать выводы по одному сиду.
5. Трактовать усечение по времени как терминальное состояние.
6. Не нормировать действия и наблюдения.
7. Менять алгоритм до воспроизведения эталонной кривой с эталонными гиперпараметрами.
